# Packy 开发计划修订稿

日期：2026-10-15。状态：P1—P5 代码已实现，P6 验证进行中；原生交互与 Windows 验收尚未完成。
基线：[PRD v0.2](PRD-v0.2.md)、[项目架构](ARCHITECTURE.md)。

## 1. 已确认方向与执行门槛

采用 Tauri 2 + Vue 3，服务端与更新核心使用 Rust。来源为 Modrinth、CurseForge、GitHub、Rust 服务端四类字典。客户端按已取得记录执行与重试，不协调最新发布。只处理本次 ADD/REPLACE/REMOVE，名单外不处理，不实现不同发布 ID 空差异流程。

业务 modid 唯一，Mod 名称可重复。JWT 登录与基础 RBAC；SQL 初始化超管、普通用户角色和首个超管账号。注册固定普通用户，超管管理用户、权限及实时注册开关。

用户现已授权完整 Rust app/server 按阶段实现和自审，各阶段自动推进；不推导 Commit、Push 或发布授权。实际进展见 ../.agent/tasks/rust-full-implementation.md，结构规范见 decisions/0001-rust-layers.md。

## 3. 验收矩阵

| 编号 | 场景 | 预期 |
|---|---|---|
| A1 | SQL 初始化及重复执行 | 建立两种角色、权限和首个超管；重复执行不覆盖已有密码/配置 |
| A2 | 登录、无 JWT、过期/错误签名、账号禁用 | 正确认证与拒绝；敏感信息不进入日志 |
| A3 | 注册夹带角色字段、普通用户越权 | 注册只能普通用户，不能获取超管或管理权限 |
| A4 | 超管用户管理与权限调整 | 后端按当前 RBAC 校验，前端隐藏菜单不是唯一控制 |
| A5 | 开关开/关、旧页面提交、并发注册 | 无重启实时生效；开关判定与建号同事务，按提交顺序判定 |
| S1 | 四类字典配置、禁用、引用保护 | 后续计划遵循配置；已取得记录不变化，无启用来源则明确失败 |
| S2 | 重复名称、重复 modid、原记录改 modid | 名称可重复，modid 冲突拒绝；历史快照及关联不变 |
| S3 | 同版本、增/替/删、跨版本差异 | 同版本无下载；变更生成明确路径与完整文件信息，确定顺序 |
| S4 | 草稿冲突、非法路径/哈希、发布事务失败 | 拒绝发布或回滚事务，当前指针及历史快照不被破坏 |
| S5 | Modrinth API、CurseForge/GitHub 文件录入 | 超时/限流明确；无有效直链或 SHA-512 不发布；不把其他哈希混用 |
| S6 | Rust 文件上传/下载、任意路径请求、未授权上传 | 计算真实哈希、不可变寻址；玩家可用既有 URL 下载，不能读取任意文件 |
| U1 | 取得计划后计划接口不可用或服务端发布新版 | 仍按原记录执行；server 来源的文件服务可用性单独判断 |
| U2 | 并发下载、重试、切换源、未知大小 | 上限 4；总尝试有界；不虚报进度，不回服务端刷新计划 |
| U3 | 下载失败、哈希错误、取消 | 原游戏文件不变，失败不写成功版本 |
| U4 | 新增、同/不同路径替换、显式删除 | 仅名单路径变化；所有名单外文件逐字节不变，无玩家 Mod 扫描 |
| U5 | 部分安装失败、重启及原记录重试 | 仅重做该任务；不存在旧路径的删除可重试，不引入新任务 |
| U6 | 文件完成但本地版本保存失败 | 不提示成功、不启动；保留原任务重试入口 |
| U7 | 路径穿越、中文/空格、链接逃逸、占用/权限失败 | 指定路径安全检查；合法路径可用，文件错误明确 |
| U8 | 多进程与重复点击、整包移动 | 单写入者；以 exe 目录定位，名单外不受影响 |
| U9 | 仅检查网络失败、安装失败、本地任务损坏 | 仅检查失败可离线启动；未完成安装不启动、不猜新计划 |
| E1 | Windows 10/11 x64 与 WebView2 | 实际桌面启动、缩放、中文、下载期间响应正常 |
| E2 | 真实整合包增/替/删/跨版本与启动器 | 目录结果、版本记录、HMCL/PCL2 调用符合配置 |
| E3 | JWT 登录→字典/系统设置→发布→四源下载 | 实际 HTTPS 链路；模拟和真实来源证据分别记录 |
| E4 | Windows 文件占用、中断、SQLite 重启 | 失败提示与原任务重试可验证；重启后设置仍持久有效 |

取消上一稿玩家 Mod 来源识别/冲突管理、空差异版本推进、服务端协同恢复的测试要求。只检查本次计划中的路径合法性，不把它扩大成全目录扫描。

## 4. 验证与交付边界

Rust 核心采用匹配范围的单元/集成测试、cargo fmt 与 cargo clippy。数据库测试使用临时 SQLite，文件测试使用整包副本，第三方网络以受控服务测试异常并另作有限真实验证。Windows 实机验证不以 Linux 通过代替。

Vue 和管理端执行类型检查与构建；实际 Tauri 窗口的视觉和交互由用户验收。AI 生成 UI 不免除接口与授权检查。SQL 初始化说明包括密码哈希准备和注册开关，部署者决定是否开放注册。

每阶段交付运行命令、通过/失败/未执行项目和下一步，不承诺未经测量的性能或工期。
