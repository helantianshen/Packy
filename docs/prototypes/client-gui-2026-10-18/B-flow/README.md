## 状态与交互契约

- 首页主操作打开变更确认；确认后才开始更新。清单说明是固定约束，不是可关闭选项。新增没有旧文件，移除没有新文件
- 检查中可以取消，未知目标版本和更新数量不显示猜测值
- 下载与校验可取消；已下载字节、总量、速度来自实际状态。总量未知用不定进度，不显示虚假百分比；没有暂停功能
- 全部下载校验通过后才安装；安装和保存阶段禁止取消或退出，不提供游戏启动。图中不定进度不承诺按文件计算的精确百分比
- 完成必须在版本保存成功后显示；按钮调用已有启动器，不暗示直接进入游戏
- 有任务的失败或取消只能重试原任务，不刷新为最新计划；校验错误不标成网络错误。图中失败样例仅为下载超时
- 无任务的检查失败提供重新检查；未初始化或版本缺失提示维护者处理，不自动猜测版本
- 实际是否允许打开启动器由 can_launch 决定，不能由设计页自行推断
- 后台开关默认开启。配置页业务地址、目录和启动器只读，只有主题与后台行为可调整

## 原型与实现边界

图中为生成图片，文字、数值、标识是演示数据，不是实测应用截图或生产资源。版本展示在真实协议只有 release ID 时需要明确使用 ID 简写，不凭空生成语义版本。完成图、安装图和失败图用于各自独立状态，不能组合成同时可操作的界面。

本轮保留人工协议和核心行为。用户确认后才进入可交互 HTML/Vue 原型及实际 GUI 实现，并进行 Playwright 和原生 Electron 验证。图像审查不能替代键盘、焦点、动效、缩放、窗口尺寸和系统托盘验收。

建议动效：切换主题采用短色彩过渡；检查与不定进度仅轻量循环；进度数字不跳动布局；减少动态效果偏好下关闭非必要动画。图稿不能证明这些交互已经实现。

使用 Impeccable 约束流程，以内置 ImageGen 基于已选图片生成；精确提示词保存于 prompts.json。参考来源沿用上轮已完成网络研究，不新增未经核实的产品能力。

## 本轮图片检查

四张最终图均已查看。初版失败页错误包含“重新检查”，已定向重绘并确认移除；最终以 03-complete-retry.png 为准。安装页的条纹进度应实现为不定动画，不解读为图中长度对应的完成比例。插画和图标属于生成示意，实施前需要单独准备资源，不裁切整张 UI 图冒充组件。

## 审查结论补充

用户认为流程没有大问题，并要求图标、明暗背景可替换，以及不同组件采用独立尺度，禁止整体等比例缩放。官方规范调查、Packy 尺寸表、响应式规则和资源替换边界见 [layout-and-branding.md](layout-and-branding.md)。
