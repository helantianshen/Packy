# B 方案组件尺度与可替换资源

2026-10-18。用户认可流程原型，补充要求：图标与明暗背景可替换，界面不得整体等比例缩放。本文记录实施约束与调查结论；GUI 已按此方向实现，实际验证见 docs/client-gui-verification.md。

## 官方规范证据

调查的是成熟产品背后的公开设计系统，不声称测量了其闭源客户端。

| 来源 | 可核查事实 | Packy 如何采用 |
| --- | --- | --- |
| [Microsoft Fluent Typography](https://fluent2.microsoft.design/typography) | Web 正文 14/20，副标题 16/22、20/26，标题 24/32、28/36、32/40；不同平台使用适合的系统字体 | 按语义角色设字号和行高，不随窗口宽度连续缩放所有文字 |
| [IBM Carbon Button specifications](https://www.carbondesignsystem.com/building-blocks/core/components/button/specifications) | 按钮有独立尺寸档位，常用 32、40、48px | 工具操作、普通操作、主操作分档，不按截图比例计算 |
| [Adobe Spectrum Spacing](https://spectrum.adobe.com/foundations/layout-and-structure/spacing/overview) | 页面间距和组件间距服务不同目的，变化速率不同 | 窗口增大主要改变外边距、列宽和留白，组件内边距保持稳定 |
| [Adobe Spectrum Icons](https://spectrum.adobe.com/foundations/icons-and-illustrations/using-icons) | 图标图形尺寸与所在画布不同，使用离散尺寸并考虑光学对齐 | 图形 16–20px 与点击区域 32–40px 分开，不把小图标等同小点击区域 |

以上是外部事实；以下数值是结合中文、B 方案和当前窗口的 Packy 初始设计值，需以实际渲染验证，不冒充上述产品统一标准。

## 组件尺度

单位为 CSS 逻辑 px；不是截图物理像素。字体实现用 rem，以 16px 根字号换算；不动态改 root font-size 来适配窗口。

| 部件 | 初始值 | 布局行为 |
| --- | --- | --- |
| 系统标题栏 | 交给系统/平台适配 | 原生控制位置与拖动区域不按概念图硬编码；应用导航不冒充系统菜单 |
| 应用导航栏 | 高度下限 52；文字 14/20；品牌图形 24 | 宽度弹性，极窄/文本放大时允许增高，不整体缩小 |
| 正文、路径、表格 | 14/22 | 长内容换行；路径 overflow-wrap:anywhere，不以缩小字号塞入 |
| 辅助说明 | 12/18 或 13/20 | 不使用原实现中的 9–10px 承载重要信息；错误与操作仍用正文级 |
| 分区标题 | 16/24、字重 600 | 与正文清楚区分，不滥用大标题 |
| 包名、阶段标题 | 24/32；窄窗口 22/30 | 最多按断点切档，不用 vw 无限增减；包名允许换行 |
| 版本/摘要数值 | 20/28、表格数字等宽 | 不比任务标题更抢眼，长 ID 用明确简写并可查看完整值 |
| 普通按钮 | 最小高 36；文字 14/20；水平 padding 16 | 宽度由文案决定；文字放大可增高；同一操作组等高 |
| 主要操作 | 最小高 40；文字 14/20、字重 600 | 用颜色与位置突出，不扩大成广告按钮；与相邻次按钮等高 |
| 图标按钮 | 点击区域 36×36；图形 18–20 | 有可访问名称和焦点框；图形不是点击区域边界 |
| 表格行 | 最小高 44；上下 padding 10 | 多行内容自动增高，不裁切路径或错误信息 |
| 卡片/内容块 | padding 20–24；窄窗口 16；间隔 16–24 | 内外间距分别设 token，不随画布等比缩放 |
| 包头插画 | 正常高度约 160；紧凑高度约 112 | cover 裁切，不拉伸；正文不依赖插画中的文字或留白 |
| 确认框 | 宽度 min(560, 可用宽度减32)；最大高可用高度减32 | 中部内容可滚动，按钮保持可达；不把整个弹窗缩小 |

## 窗口与重排

当前 BrowserWindow 默认 1060×760、最小 720×560 是外框尺寸；CSS 断点以实际内容 viewport 为准，不能混用。

- 内容宽度 ≥1000：页面最大宽 1120 居中，边距 24–32；配置双栏，摘要四列
- 800–999：边距 24，保留主要分区，压缩装饰区域与空白，不改正文/按钮尺度
- <800：边距 16，配置改单栏，摘要改两列，底部提示与按钮分行，表格转逐条布局或按内容换行
- 内容高度 <620：包头用紧凑高度，非必要插画缩减；主内容滚动，不靠缩小所有控件塞满
- 任何状态使用相同窗口尺寸，不因下载/完成内容变少就自动缩窗；生成图中不同高度只表达信息量
- 禁止根容器 transform:scale、随窗口改 zoom 或用单一缩放系数计算所有尺寸
- 系统 DPI 与用户主动缩放应正常生效，不用反向缩放抵消；文本放大时使用 min-height 与重排避免裁切
- 按钮区若 sticky，必须留占位且不遮挡表格最后一行；弹窗打开后焦点受控，Escape 不得绕过安装退出保护

## 可替换品牌资源

按整合包维护者替换素材设计，不新增玩家的业务配置权限。生产实施采用包外独立 branding 目录，首次提供随包默认素材；维护者替换同名文件后重启生效，不需要修改 Vue 代码或重新编译 Go。

目录位于整合包根目录 `.updater/branding/`：

- `logo.png`：界面品牌标识；透明正方形，建议 512×512，界面按 contain 展示
- `background-light.webp`：浅色主题包头插画
- `background-dark.webp`：深色主题包头插画
- `tray.png` 与 `tray@2x.png`：小尺寸专用图形，不把复杂封面硬缩成托盘
- `trayTemplate.png` / `trayTemplate@2x.png`：macOS 模板托盘图，按系统明暗处理

背景建议至少 1600×600，主题独立取图，使用 object-fit:cover 与固定遮罩保证文字可读。资源内不嵌入标题、按钮或状态文案。修改背景不会改变文字字号、组件尺寸或内容位置。缺失或损坏时回退到随包资源，更新功能继续可用；不要求两张都存在才启动。

资源读取只开放固定品牌文件名，验证格式/尺寸和文件大小，拒绝目录穿越和符号链接逃逸；渲染进程不获得任意文件读取能力。沿用 Main/preload 安全边界，通过固定 IPC 返回经验证的 PNG/WebP data URL，CSP 仅允许自身和 data 图片，不依赖网络 URL。不要为品牌替换开放 server_url、pack_id 或游戏路径的运行时覆盖。

系统应用图标是另一层：仓库品牌源文件统一维护，Windows 构建使用含多尺寸的 ICO，macOS 使用 ICNS，Linux 使用 PNG及平台集成资源。改变可执行文件/应用包图标需重新打包，macOS 签名后修改包内资源可能影响签名。界面图标/背景包外替换与系统图标重打包必须在说明中分清。托盘模板规则及图像格式见 [Electron nativeImage](https://www.electronjs.org/docs/latest/api/native-image)，窗口平台行为见 [BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window)。

## 实施验收

- 明暗主题分别检查 720×560、1060×760、1440×900 窗口，并记录实际 viewport；检查短窗口滚动与弹窗
- 100%、125%、150%、200% 用户缩放；长中文包名、长路径、长错误、未知下载大小、不同比例替换背景
- 替换/删除/损坏 logo 和两张背景，验证成功加载或默认回退；主题切换不出现另一主题背景闪烁
- 检查表格、菜单、按钮与正文尺度保持稳定，窗口变化只有容器重排和有限档位变化
- 浏览器截图验证布局；Electron 原生验证标题栏、托盘、DPI和资源加载；Linux 不替代 Windows/macOS 验收

已完成实现；上述验收清单不是全部平台已通过的声明，实际已执行项与限制见 [GUI 验证记录](../../../client-gui-verification.md)。
